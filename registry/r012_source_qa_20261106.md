## Additional data-identity options

NCAA team-roster 2026: **5,633** rows / 16 fields; 2027: **5,587** rows / 16 fields. Both supply `team_id`, `player_id`, `clean_name`, GP/GS, but **not previous-season player minutes**. ESPN player core 2026/2027 supplies athlete IDs, not historically reliable team membership by itself. All these counts are decoded file footers, not parsed records.

NCAA possessions and NCAA player box share `contest_id` and `espn_game_id`. NCAA player box also has `team_espn_team_id`. ESPN game rosters contain `game_id`, `team_id`, `athlete_id`, active/DNP flags. Preserve NCAA and ESPN native identifiers separately; never equate NCAA player IDs and ESPN athlete IDs without corroboration.

## Executable research-only source QA

* Runner: [scripts/cbb_r010_source_qa.py](../scripts/cbb_r010_source_qa.py)
* Tests: [tests/unit/test_cbb_r010_source_qa.py](../tests/unit/test_cbb_r010_source_qa.py)
* **Six of six synthetic local unit tests passed.** Local repository-like layout also passed all six.
* Missing-input dry run exits code 2 with explicit `BLOCKED_MISSING_SOURCE`; no fake data is produced.
* The runner performs conservative exact-identity join checks, flags duplicate possession identifiers, active/DNP contradictions, and missing previous-season minutes. It does NOT create predictions or change live master data.

Run in a **network-enabled, pyarrow-enabled** environment:

```bash
python scripts/cbb_r010_source_qa.py --fetch --source-dir data/raw/r012 --output-dir data/research/r012 --partial --team-box --report-json
python -m unittest discover -s tests/unit -p 'test_cbb_r010_source_qa.py'
```

`--partial` requires the three row-level sources available and permits the large ESPN season-roster source to remain missing. Full processing without `--partial` requires all four. The script fetches raw GitHub files but does not certify a historical publication timestamp.

## Blockers and gates

1. Decode actual ZSTD Parquet records, independently validate game pairs and contest/ESPN crosswalk coverage. No verified 2026-27 ingestions yet.
2. Retrieve ESPN season rosters or use the NCAA team roster player-ID path, with explicit differences and source PIT restrictions.
3. Obtain and validate previous-season player minutes, team-season membership, and **pre-forecast roster publication timestamps**. Only then compute returning-minutes/production measures.
4. Use prior-game rotations only when truly before forecast freeze. Current-game active/DNP is **postgame** data.
5. On identical games, compare team-only versus player-aware cold-start models with strict chronological and then genuinely prospective validation.

Legacy CBB-Q-004 (PBP reconstruction) and CBB-Q-013 (returning-player skill stability) already have sufficient legacy evidence. Do not reopen simply to repeat old tests. Prior 2025-26 historical sample has been examined repeatedly and is consumed.
